## 写作落实

| 维度 | 本稿采用的做法 |
| --- | --- |
| 标题 | 清楚交代任务和可供读者借鉴的设计。 |
| 导语 | 从技术使用或评测中遇到的具体问题切入。 |
| 节奏 | 编号章节，先直觉再细节，关键条件用列表或表格。 |
| 技术深度 | 论文解读讲设计与证据；实战复现才加入环境、命令与故障排查。 |
| 图表 | 框架、数据/评测划分、性能与失败分析，各有解释。 |
| 结尾 | 代码与数据入口、使用边界，区分论文报告与本地实测。 |

建议 1800–3000 中文字。不要给所有论文强加复现教程，也不臆造显存、时延和部署结论。

## ARGUS 原创适配示例

**标题：** 从观察证据到裁判判断：ARGUS 视频鉴伪框架与评测设置解析

**导语：** 想借鉴一种视频鉴伪方法，除了看结果，还需要弄清系统怎样处理输入、模型如何训练，以及测试数据与训练数据怎样分开。ARGUS 提供了一个多智能体方案：先由四个观察者记录证据，再由裁判判断。本文按系统流程梳理这项研究，并说明其开源资料与评测边界。

**正文大纲：** ① 任务与资源；② 观察者到裁判的处理流程；③ SFT 与 GRPO 的训练分工；④ 训练数据及未见生成器测试划分；⑤ 三项主指标如何一起看；⑥ 代码、数据入口与尚未实测的事项。

**图表安排：** 系统流程图 → 数据概览图 → 带测试条件的结果表。ARGUS 当前采用论文解读模式，不写“已跑通”；用户另要复现时再执行并记录实测。
