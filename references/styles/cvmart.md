## 写作落实

| 维度 | 建议写法 |
| --- | --- |
| 标题 | 清楚交代任务和可供读者借鉴的设计。 |
| 导语 | 从技术使用或评测中遇到的具体问题切入。 |
| 节奏 | 编号章节，先直觉再细节，关键条件用列表或表格。 |
| 技术深度 | 论文解读讲设计与证据；实战复现才加入环境、命令与故障排查。 |
| 图表 | 框架、数据/评测划分、性能与失败分析，各有解释。 |
| 结尾 | 代码与数据入口、使用边界，区分论文报告与本地实测。 |

建议 1800–3000 中文字。不要给所有论文强加复现教程，也不臆造显存、时延和部署结论。

## 结构与图文安排

技术问题与资源 → 系统输入输出及设计 → 数据与评测划分 → 训练 → 性能与失败分析 → 开源入口和使用边界。

系统流程图跟随输入输出说明；数据图用于解释评测条件，原论文结果截图后分析性能取舍。论文解读不添加未经实测的命令、显存或时延，复现文章另列真实执行记录。

遵循[共同写作与交付要求](../writing.md#共同写作与交付要求)：资源网址可见、图注简短、图片有上下文，最终 Word 交给投稿者审核。结构可按论文贡献和当前栏目要求调整。
