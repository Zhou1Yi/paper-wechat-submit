## 写作落实

| 维度 | 建议写法 |
| --- | --- |
| 标题 | 团队或机构信息可与方法名、核心动作及读者收益结合；身份须核实，突出贡献，允许有解释作用的比喻。 |
| 导语 | 先用具体问题建立阅读动机，再用一段话交代团队、方案与带测试条件的核心结果。 |
| 节奏 | 短段落串联问题、设计与证据；小标题直接点明本节要解释的内容。 |
| 技术深度 | 先讲机制和角色分工，再讲数据、训练及评测；说明输入输出、训练对象与奖励依据。 |
| 图表 | 论文信息旁放作者与机构截图；对比图有问题铺垫和引导句，流程图紧跟模块说明，实验截图后立即解读。 |
| 结尾 | 回到研究问题，提炼设计启发与适用边界，集中列出完整资源网址。 |

## 结构与图文安排

读者问题 → 团队、方案与主要结果 → 论文与项目 → 设计动机 → 方法及模块 → 数据与训练 → 主实验 → 关键消融 → 结语与资源。

概念对比图回答“为什么需要这个设计”，放在问题说明之后；详细流程图回答“系统怎样工作”，放在角色、模块或输入输出说明之后。每张图前用一句话说明读图目的，图注只概括内容，不重复正文。实验截图保留表头、指标与比较条件，图后解释核心差异和局限。

正文约 1800–2800 中文字，可按内容调整。遵循[共同写作与交付要求](../writing.md#共同写作与交付要求)。已审定标题和作者修改优先保留，不能为了统一模板而覆盖；学习表达方式不等于将样稿中的模型名、数值和排名直接用于其他论文。
