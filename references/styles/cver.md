## 写作落实

| 维度 | 建议写法 |
| --- | --- |
| 标题 | 任务、方法与贡献明确；不擅加 ECCV、CVPR 等录用前缀。 |
| 导语 | 简短指出问题，紧接论文信息和资源卡。 |
| 节奏 | 明确的小节与贡献列表，必要处用通俗直觉过渡。 |
| 技术深度 | 讲清模块输入输出、训练阶段与消融含义，不只翻译摘要。 |
| 图表 | 框架图跟随模块解释，结果表后分析有效条件和失败情况。 |
| 结尾 | 提炼技术贡献和代码入口；不复制公众号推广、媒体署名。 |

建议 1800–3000 中文字。公式只在解释机制时引入，不为“像技术号”堆公式。

## 结构与图文安排

任务与论文资源 → 设计动机及贡献 → 框架与模块输入输出 → 训练阶段 → 评测协议、主结果与消融 → 局限和代码。

概念对比图先有问题铺垫，完整框架图跟随模块介绍；数据分布图只在解释划分时使用。主实验和关键消融采用原论文截图，配文说明指标、控制变量和结论范围。

遵循[共同写作与交付要求](../writing.md#共同写作与交付要求)：资源网址可见、图注简短、图片有上下文，最终 Word 交给投稿者审核。结构可按论文贡献和当前栏目要求调整。
