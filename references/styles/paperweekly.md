## 写作落实

| 维度 | 建议写法 |
| --- | --- |
| 标题 | 研究问题与方法贡献明确，强调解决的具体缺口。 |
| 导语 | 给出设计动机和关键判断；作者卡须由投稿者确认。 |
| 节奏 | 章节层次清楚，逐步回答“为何这样设计、证据是什么”。 |
| 技术深度 | 任务定义、训练目标、实验协议、消融与局限完整连贯。 |
| 图表 | 方法图与模块论述对应，实验表后分析原因和失败条件。 |
| 结尾 | 研究启发、适用边界、后续问题与资源。 |

建议 2200–3500 中文字，必要公式解释变量后使用。作者解读与编辑综述的叙述身份不同：未确认用户是作者时使用“研究团队”，不擅写“我们提出”。

## 结构与图文安排

研究缺口与论文信息 → 设计动机 → 方法和训练目标 → 数据及评测协议 → 主结果、消融与错误分析 → 局限和开放问题。

先定义问题再引出概念对比图，完整框架跟随机制解释。主实验与消融优先采用原论文截图，保留比较条件和重要脚注，配文解释结果如何支持或限制设计假设。必要公式解释符号，避免只罗列数值。
