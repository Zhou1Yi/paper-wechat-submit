## 写作落实

| 维度 | 建议写法 |
| --- | --- |
| 标题 | 方法或资源亮点明确，必要结果带条件。 |
| 导语 | 用读者能理解的直觉引出具体研究问题。 |
| 节奏 | 资源卡靠前，分项解释关键改进，避免连续堆术语。 |
| 技术深度 | 模块直觉与机制同时给出，解释为何值得关注。 |
| 图表 | 图解承担说明任务；结果后接分析，而非只罗列数字。 |
| 结尾 | 研究价值与局限、代码数据；评论与实验事实分开。 |

建议 1600–2800 中文字。不要冒用“CV君认为”的个人署名；可用“讨论”写有依据的分析。

## 结构与图文安排

问题与直觉 → 团队及论文资源 → 方法图解 → 训练与评测条件 → 定量、定性证据 → 研究点评与资源。

用任务案例建立直觉，再解释模块并给出流程图；避免在论文信息后突然插入框架对比。实验表采用原论文截图，图后指出关键差异；点评与实验事实分开，不从单个案例推出普遍优势。
